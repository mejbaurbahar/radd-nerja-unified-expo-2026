Radd AI · Nerja AI · what to add, how it works, what it is worth

Turn Radd from a place where customers chat into a place that shows how much money chat makes

Radd handles conversations very well. It cannot see what a shopper did on the store before writing, and it cannot show a merchant how much revenue its messages produced. Nerja AI already does both. This report explains, in plain language, which Nerja features Radd can add, how each one would work inside Radd's real screens, and what it takes.

The gap

Radd sees a shopper only after they send a message. Nothing about the visit before that, and nothing about whether a chat ended in a sale.

The idea

Add Nerja's store tracker, event-triggered messages and revenue attribution behind Radd's existing inbox. Radd stays the place where humans and AI talk to customers.

The payoff

Merchants get a "Revenue" screen showing what Radd recovered. Agents see the shopper's cart before replying. Radd gets a measurable reason to charge more.

The catch

Some Nerja features are built but not deployed yet, a few have known gaps, and WhatsApp template links need a design. The rollout section shows the order that avoids the traps.

What Radd can add from Nerja

11 features · each with how, benefit and effort

Each card says what the feature is in Nerja, where it would appear in Radd, how it works step by step, who benefits, and what to watch. Cards marked "See it" link to a mockup of the Radd screen.

Which ones first? Value against effort

Value is an assessed score of how much a feature helps Radd prove revenue. Effort is relative engineering work. Neither is a measurement.

F1

Store tracker: know what shoppers do

Nerja's "NerjaTag" script, offered in Radd as a Settings page

What it is

One line of code on the merchant's store. It notes product views, add to cart, checkout start and the moment a shopper types their phone number. It never records passwords, card or ID fields.

Where in Radd

New page: Settings → Store tracker.

How it works

  1. Merchant pastes the line into the store (Shopify, WooCommerce, Salla or any site).
  2. Radd shows "Verified" when the first event arrives.
  3. When a shopper types a phone at checkout, the anonymous visit is linked to that phone, which matches a Radd contact.

Benefit

  • Merchant: Radd finally sees store behavior.
  • Everything else: F2 to F6 depend on this data.
EffortMediumReadinessUsed on nerja.aiWatchConfirm product views arrive in productionSee it →
For engineers
  • Script is about 105 KB raw / 33 KB gzipped. Batches every 1 s or 15 events to POST /v1/events/batch, with a localStorage outbox and a 30-minute rolling session.
  • Consent levels none, identity, full; password, card, CVV, SSN, PIN fields are always dropped.
  • Origin allow-list per key. The Shopify web-pixel route has never been seen delivering events; use the script tag first.
  • Identity bridge: UserProfile.anonymousIds[] in Postgres joins to events in Mongo.

  2. Radd's page reads summaries from Nerja and draws the funnel.
  3. A live feed shows events as they happen, which also proves the tracker is working.

Benefit

  • Merchant: sees which products attract views but not sales.
  • Radd: a demo-able page that makes the tracker feel real.

F3

Revenue proof: credit orders to messages

Nerja's attribution engine and Revenue page

What it is

When Radd sends a link, the click is remembered with a signed token. If an order follows within the tenant's window (1 to 30 days), the order is credited to that message. Radd shows the total.

Where in Radd

A Revenue panel on the Dashboard and a Revenue page with the order ledger.

How it works

  1. Link in the message carries a signed token.
  2. Shopper clicks and buys, on the same device or another one.
  3. The order webhook or the tracker's purchase event is matched by token, then by phone or email.
  4. Radd records revenue once per order and shows it by campaign.

Benefit

  • Owner: sees what Radd earned.
  • Radd: a number that justifies price and reduces churn.
EffortMedium to largeReadinessLocal-verified, not deployedWatchFix refunds and links in templates firstSee it →
For engineers
  • Last-click model, HMAC-signed nak_at token, idempotent per (session, order). Read API: /v1/attribution/summary|campaigns|products|customers|orders.
  • P0 gaps in Nerja's own status doc: refunded orders are never reversed; multi-currency totals are summed unconverted; DOM-detected purchases carry no order id.
  • Meta templates: Nerja does not wrap template links because it breaks parameter matching. Use a URL button with a dynamic suffix carrying the token, and spike it against a real approved template.
  • For donation tenants use the Jood/Moyasar payment confirmation as the conversion event.
F4

Triggered broadcasts: message when a shopper stalls

Nerja's event campaigns and send-decision rules

What it is

Today a Radd broadcast goes to a list at a set time. A triggered broadcast sends one approved WhatsApp message to one person after something happens, such as leaving items in the cart for 30 minutes.

Where in Radd

Inside the existing Broadcast → Create wizard, as a new send type.

How it works

  1. Pick a recipe: cart left, product viewed three times, checkout stalled.
  2. Pick a template and a wait time.
  3. Safety rules apply automatically: consent, one message a day, quiet hours, stop when an order arrives.
  4. If the order comes first, the message is cancelled.

Benefit

  • Merchant: recovery runs without anyone remembering to send.
  • Radd: the rules protect the WhatsApp number from spam flags.
EffortLargeReadinessBuilt, production use unverifiedWatch24 h window and template rulesSee it →
For engineers
  • Rules mirror preset-decision.ts: consent, daily cap, quiet hours 21:00–08:00 local, collision with an active campaign of the same type, stop on conversion, escalation Email → SMS → WhatsApp → Push.
  • The engine fails open when timezone is unknown. For Saudi numbers default to Asia/Riyadh.
  • Abandonment segments (browse, cart, checkout) are recomputed hourly by a worker.
F5

Audience from a sentence

Nerja's Audience Studio

What it is

Type who you want to reach in plain words. Radd turns it into a contact group, using store behavior as well as contact fields.

Where in Radd

New option in Broadcast → Create → Target audience.

How it works

  1. Merchant writes the audience in English or Arabic.
  2. Radd shows an estimated size and how many are reachable on WhatsApp.
  3. Merchant saves it as a normal contact group and uses it.

Benefit

  • Merchant: precise targeting without learning filters.
  • Radd: targeting today is limited to groups and labels.
EffortSmall to mediumReadinessDeploy-gated at last doc updateWatchArabic quality untestedSee it →
For engineers
  • Browser → Radd → Nerja /v1/audiences/resolve and estimate → Python service → model → audience spec → deterministic resolve over events. Prompts containing emails or phone numbers are rejected before any model call.
F6

Shopper panel in the inbox

Nerja's profile, events and merchant feed

What it is

A side panel in WhatsApp Chat and Live Chat that shows the shopper's cart, recent activity, past orders and which campaign started the chat.

Where in Radd

Right side of WhatsApp Chat and Live Chat.

How it works

  1. Chat opens; Radd looks up the shopper by phone.
  2. Panel lists cart items, recent events and lifetime orders.
  3. The AI suggests a reply based on the same data; the agent edits and sends.

Benefit

  • Agent: no more "what were you looking at?".
  • Merchant: faster, more relevant replies.
EffortMediumReadinessAPI existsNeedsF1 firstSee it →
For engineers
  • Data from Nerja profile and merchant-feed endpoints (products, offers, orders), matched on phone. Suggested replies must draw only from the product list the panel shows.
F7

Safer AI agent with a knowledge base

Nerja's chat guard and per-tenant knowledge base

What it is

Rules that keep the AI inside the shop's own facts: it answers only from the merchant's products and documents, refuses off-topic or manipulative messages, hands over to a human when unsure and stops when the customer says STOP.

Where in Radd

Settings → WhatsApp Chat → AI Agent.

How it works

  1. Merchant uploads return policy, delivery terms, FAQs, or imports from a URL.
  2. Agent answers from those and the catalog.
  3. Unsure or angry: it hands over with the context.

Benefit

  • Merchant: brand-safe automation.
  • Radd: fewer incidents to support.
EffortMediumReadinessSimulator-tested onlyWatchReal-model quality unverifiedSee it →
For engineers
  • Radd's agent is an external service, so adopt the rules, not the code: retrieval-only answers, inbound probe screen, outbound leak and foreign-link screen, handoff on low confidence, flood cap per conversation per hour, STOP suppression. Knowledge API: /v1/knowledge/documents, /documents/from-url, /:id/search.
F8

Consent and opt-out records

Nerja's consent log, suppression list and data-request jobs

What it is

A record of who agreed to be messaged, who opted out and when, plus tools to export or delete one person's data on request.

Where in Radd

New columns and filters in Contacts.

How it works

  1. Consent is captured at the store or in chat and stored per contact.
  2. Triggered messages (F4) refuse to send without it.
  3. STOP and delete requests are honored everywhere.

Benefit

  • Radd: required before automated messaging to Saudi residents is safe to sell.
  • Merchant: fewer complaints and number blocks.
EffortMediumReadinessEndpoints existWatchLegal wording neededSee it →
For engineers
  • /v1/privacy/consent, /suppress, /access, DELETE /subjects, /jobs/:id. Tenant consent mode: opt-in or opt-out.
F9

Backup channels: email and SMS

Nerja's multi-channel sender

What it is

If a WhatsApp message is not read in time, send an email, then optionally an SMS.

Where in Radd

An option inside the triggered broadcast wizard, and a Channels settings page.

How it works

  1. Merchant connects an email provider and an SMS gateway.
  2. Chooses the wait before each fallback.
  3. A converted shopper stops the chain.

Benefit

  • Merchant: reaches people without WhatsApp or with undelivered messages.
EffortMediumReadinessNeeds Saudi SMS gatewayWatchUnread is a weak signalSee it →
For engineers
  • Nerja supports SES, Resend, AutoSend for email and Twilio, BulkSMSBD for SMS. BulkSMSBD is Bangladesh-specific, so choose a local gateway and confirm sender-ID registration before promising SMS.

      Cost and value

      Radd sells Trial (free), Advance at SAR 560 and Premium at SAR 899. Two pricing shapes fit: a Revenue add-on on Advance that Premium includes, or an included event allowance per plan with metered overage, since event volume is what costs money to run.       The calculator uses inputs, not findings. Attributed revenue is not extra revenue: it includes sales that might have happened anyway. Only a holdout group (some shoppers never messaged) can measure the true lift.

      RiskWhy it mattersWhat to do
      Built is not liveNerja's own docs say CI builds the image but nobody rolls the Lambda automatically, and schema changes are not applied by deploy.Make "deployed and database updated" part of done for every feature. Have DevOps own a staging update before the pilot.

      Decisions needed

      1. Option A (use Nerja as the engine) or B (rebuild)? A is recommended and changes the staffing plan.
      2. Who owns the WhatsApp number and campaign threads, Radd or Nerja?
      3. Is the target still an online store, or any tenant with a conversion, including donations and bookings?
      4. Which one or two merchants pilot, and will they install the tracker?
      5. Who at DevOps updates Nerja's services and database for this work?
      6. Which SMS gateway for Saudi numbers, and who registers sender IDs?
      7. Does legal approve consent wording before triggered messages send?

      Appendix

      Plain-language glossary
      Tracker
      A small script on the merchant's website that records shopper actions such as viewing a product.
      Event
      One recorded action, for example "added to cart".
      Template
      A WhatsApp message pre-approved by Meta. Businesses must use one to message someone first.
      24-hour window
      After a customer writes, a business may reply freely for 24 hours. After that, only templates.
      Attribution
      Deciding which message earned an order. Here: the last link the shopper clicked within the window.
      Opted in
      The person agreed to receive messages.
      Knowledge base
      Documents and facts the AI is allowed to answer from.
      Deploy-gated
      Finished in code but not yet running in production.
