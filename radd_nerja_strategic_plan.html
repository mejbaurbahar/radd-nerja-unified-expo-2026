Supersedes Blueprint v2.4 · built from source code and the live Radd dashboard

What Radd should take from Nerja, and how to do it without over-promising

v2.4 had the right instinct: Radd cannot see what shoppers do before they message, and Nerja can. It was written from screenshots of Nerja's dashboard. This version is written from Nerja's code and docs and a read-only pass over the live Radd app. It corrects the mistakes, adds the Nerja capabilities that were missed, and replaces the 12-week plan and the revenue claims with things that can be defended.

1. Verdict

Read this if nothing else
Keep

The thesis

Radd's moat is the human and AI inbox. What it lacks is behavior data and proof of revenue.

Change

Integrate, don't rebuild

Nerja already has the tracker, event pipeline, campaigns, attribution and consent tooling. Using it as the engine behind Radd's inbox is faster than a 12-week rebuild.

Risk

Merged is not live

Several Nerja features are verified locally but not deployed to Nerja's production. A plan that assumes they are live will slip.

5. Features to bring, ranked

Assessed scores, not measurements

Value is how much a feature advances Radd's goal of proving revenue, not just handling chats. Open a row for the how and the watch-outs.

F1Behavior tag and identity bridge
Effort M · Reuse high · Phase 1

How

Serve Nerja's tracker under a Radd-branded key and domain. Add a "Store tracker" settings page in Radd with the snippet, last event received and a ping test. The key join is phone to anonymous id: Nerja keeps anonymousIds[] on the profile and fires phone_captured at checkout, and Radd contacts are keyed by phone.

Watch

Origins are allow-listed per key. The Shopify web-pixel path has never been seen delivering events, so start with the script tag. Confirm view_item arrives in production: in August it was missing from the live taxonomy and Browse-Abandoned stayed at zero.

F2Event analytics, read-only first
Effort S · Reuse high · Phase 1

How

A Radd page that calls Nerja's dashboard endpoints (overview, timeline, top products, event summary, recent events). Ship the funnel and top products first and the live feed after. No new storage in Radd.

F3Revenue attribution and conversion ledger
Effort M–L · Reuse medium · Phase 2

How

Reuse Nerja's signed click token and attribution records. Three things must be solved first:

  1. Meta template links. Use a URL button with a dynamic suffix carrying the signed token, or a short link generated at send time. Do not rewrite the approved template body. Needs a spike against a real approved template.
  2. Refund and cancellation reversal. Without it the ledger overstates revenue and the first finance reviewer will find it.
  3. Currency. Radd merchants are mostly SAR. Group by currency or normalize to a tenant base currency.

Generalize "order"

For donation tenants use the Jood/Moyasar payment confirmation as the conversion event.

F4Auto funnels with send-safety rails
Effort L · Reuse medium · Phase 3

How

Add a "Triggered" mode to Radd Broadcast that maps to Nerja's event campaigns. Treat the decision engine's rules as product requirements: consent first, daily cap across channels, quiet hours, one active campaign per type per customer, stop when converted.

Watch

Business-initiated messages need approved templates, so "30-minute timer then send" must respect the 24 h session rule and template category. Quiet hours need the recipient's timezone and the engine fails open when it is unknown, so default Saudi numbers to Asia/Riyadh.

F5Audience Studio in Contacts and Broadcast
Effort S–M · Reuse high · Phase 3

How

Radd targets groups and labels only. Add "Describe your audience" to the broadcast wizard, call Nerja's resolve and estimate endpoints and write the result back as a Radd contact group. Prompts containing emails or phone numbers are refused before any model call, which is worth keeping.

Watch

Arabic prompt quality must be tested. The taxonomy and prompts were built against English and Bangla examples.

F6Live shopper context drawer
Effort M · Reuse medium · Phase 4

How

Right-hand panel in WhatsApp Chat and Live Chat: cart, viewed products, recent events, lifetime spend and the campaign that started the thread, matched on phone. Suggested replies come from Radd's own AI agent using the same product list the drawer shows, so it cannot quote something the shopper never saw.

F7Guardrails and knowledge base for Radd's AI agent
Effort M · Pattern reuse · Phase 4

How

Radd's agent is an external service connected by credentials, so port Nerja's rules rather than its code: answer only from retrieved tenant data; screen inbound for injection probes and outbound for leaked secrets and foreign links; hand off whenever unsure; cap bot replies per conversation per hour; never reply after STOP. Add a per-tenant knowledge base if the agent has no retrieval.

F8Consent, suppression and DSAR
Effort M · Reuse high · Phases 2–3 · required before F4

Why it moved up

v2.4 does not mention it, but automated behavioral messaging to Saudi residents falls under the Personal Data Protection Law, and Radd already sells compliance for the region. Nerja has a consent log, tenant consent mode, suppression list and access and delete jobs. Show consent state in Radd Contacts and make F4 refuse to send without it. Counsel should confirm consent wording and retention.

F9Channel fallback: email, SMS, push
Effort M · Reuse high · Phase 5

How

Nerja's SMS options are Twilio and BulkSMSBD, a Bangladesh provider. For Saudi numbers use a local gateway and confirm sender-ID registration with the provider before promising SMS fallback. Email via SES or Resend works as is. Make fallback opt-in per tenant, since "unread" is a weak signal on its own.

F10Mobile SDK for partner apps
Effort M · Reuse high on Android · Later

Fits the partner apps in the Hajj expo story. iOS has never been compiled, so quote Android only.

F11Voice agent
Effort unknown · Park

One endpoint and no evidence of use. Leave it out of this plan.

10. Pricing and the ROI check

Do not introduce $49 / $199 / $499. Radd already sells Advance at SAR 560 and Premium at SAR 899. Two options fit what exists: a Revenue add-on on Advance that is included in Premium, or an included event allowance per plan with metered overage, because event volume is the real cost driver. Use this calculator with a merchant's measured numbers.

5.0x

Figures in the calculator are inputs, not findings. Attributed revenue is not a net gain: it includes sales that might have happened anyway, which only a holdout group can measure.

11. Decisions needed

  1. Option A (engine integration) or B (port)? A is recommended and changes the staffing plan.
  2. Who owns the WhatsApp number and campaign threads, Radd or Nerja?
  3. Is the target customer still an e-commerce store, or any tenant with a conversion, including donations?
  4. Which one or two merchants will pilot, and will they allow the tracker install?
  5. Who at DevOps owns rolling Nerja Lambdas and applying schema changes for this work?
  6. Which SMS gateway for Saudi numbers, and who registers sender IDs?
  7. Should legal approve consent wording before F4 sends anything?
